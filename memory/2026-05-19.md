# 2026-05-19 - Theme Update & Local Skills Directory

## Context
The user requested implementing a dark theme ('night' theme), persisting the theme preference in localStorage, putting the toggle button in the footer, and creating a local skills directory in the project. The user also specified that all updates (including memory and skills) must be local to this project.

## Decisions & Changes
- Refactored `Layout.tsx` theme state management. Replaced standard React `useState` and manual `localStorage.setItem` in `useEffect` with `useLocalState` from `@keldan-systems/state-mutex` using the key `'writetosee-theme'` and default `'pastel'`.
- Verified the footer toggle button in `Layout.tsx` works with the new state management.
- Created a local `skills/` directory in the project root containing `writetosee-standalone/SKILL.md`. This skill captures the project rules on state management and file storage, conforming to the AGENTS.md and community skill standards.
- Created project-local `memory/2026-05-19.md` to track changes locally.
- Cleared out all unused CSS rules in `src/App.css`, as it was not imported or referenced anywhere in the codebase.
- Fixed a TypeScript error in `Layout.tsx` by changing the `setTheme` call inside `toggleTheme` to pass a direct value instead of a functional updater, matching the API signature of `useLocalState`.
- Modified `Layout.tsx` structure to restrict outer viewport height to screen size (`h-screen overflow-hidden`) and enabled vertical scrolling directly on the `<main>` container (`overflow-y-auto`). This guarantees that the header and footer remain static/visible at all times while the page content scrolls.
- Moved centering and max-width classes (`max-w-6xl mx-auto`) from the `<main>` scroll container to an inner wrapping `div`. This ensures the scrollbar is aligned with the screen/viewport edge rather than the edge of the centered content box.
- Renamed the `Layout` component and its file to `MainLayout` (`src/components/MainLayout.tsx`) and updated its references in `src/App.tsx`. Deleted the old `Layout.tsx` file.
- Extracted inline success/error alert notification UI markup from `Welcome.tsx` and `Test.tsx` into a reusable, custom React component named `NotificationDisplay` (`src/components/NotificationDisplay.tsx`).
- Extracted the simulated LLM prompt and response inputs/actions from `Welcome.tsx` and `Test.tsx` into a reusable, custom React component named `LLMConector` (`src/components/LLMConector.tsx`) to encapsulate form state handlers and display constraints.
- Extracted directory settings, permissions connection actions, and workspace files browser listing from `Welcome.tsx` and `Test.tsx` into a reusable, custom React component named `FolderConnector` (`src/components/FolderConnector.tsx`).
- Created `clientLoader` in `src/routes/Welcome.loader.ts` to handle loading of the workspace directory permissions and files list asynchronously.
- Moved `checkDirectoryStatus` and mount `useEffect` logic from `Welcome.tsx` / `Test.tsx` into `Welcome.loader.ts` to prefetch directory handle state. Both views now initialize state from `useLoaderData()`.
- Created `clientAction` in `src/routes/Welcome.action.ts` to handle Form-based actions (intents) for writing Markdown files and PNG image blobs to the browser-connected local directory.
- Refactored `src/App.tsx` from standard `BrowserRouter` to `createBrowserRouter` to enable React Router v7 loader/action execution.
- Created/Updated `.vscode/settings.json` to enable explorer file nesting and configure nesting patterns to group `${capture}.loader.ts` and `${capture}.action.ts` under their corresponding `${capture}.tsx` component file.
- Refactored `FolderConnector`, `LLMConector`, `MainLayout`, `NotificationDisplay` components and the `Welcome`, `Test`, `About` route pages to follow the `DefaultComponent.tsx` pattern, migrating to `PropsWithChildren` and generic `HTMLAttributes` layout wrapper prop spreading.
- Added an LLM API Key input field to `LLMConector.tsx` persisted using `useLocalState` with key `'llm_api_key'`.
- Corrected and cleaned up the `LLMConector.tsx` HTML/TSX div nesting, closing tags, and trailing arrow function syntax.
- Added an external Link next to the API key input label pointing to `https://aistudio.google.com/api-keys` configured to open in a new window (`target="_blank"`).
- Configured flex layout classes on `MainLayout.tsx`'s `<main>` container and route inner divs (`Welcome.tsx`) to support 100% full-height layouts.
- Overrode the border-radius of `input`, `textarea`, `.input`, and `.textarea` elements in `src/index.css` to be exactly `4px` to achieve consistent box rounding.
- Corrected the wrapper tag and inner card nesting in `FolderConnector.tsx` to properly wrap components inside a `div.space-y-8` root container and resolve syntax warnings.
- Extracted the LLM icon span element into a standalone `LLMMarker` component inside `src/components/LLMMarker.tsx` following the `DefaultComponent.tsx` pattern, and integrated it inside `LLMConector.tsx`.
- Extracted the workspace directory status block into a standalone `LLMStatus` component in `src/components/LLMStatus.tsx` conforming to the `DefaultComponent.tsx` pattern, and replaced the duplicated inline implementations in both `LLMConector.tsx` and `FolderConnector.tsx`.
- Extracted the LLM API Key save/forget button action block to a standalone `LLMConectorActions` component inside `src/components/LLMConectorActions.tsx` following the `DefaultComponent.tsx` pattern, and imported it inside `LLMConector.tsx` mapping to key existence (`hasKey`).
- Extracted the LLM API Key input field and label block into a standalone `LLMConnectorForm` component in `src/components/LLMConnectorForm.tsx` following the `DefaultComponent.tsx` pattern, and imported it inside `LLMConector.tsx`.
- Applied the `LLMConector` refactoring pattern to `FolderConnector.tsx` by extracting its contents into `FolderConnectorHeader`, `FolderConnectorStatus`, `FolderConnectorActions`, and a commented out `FolderConnectorForm` component for the directory file browser block.
- Reverted `src/lib/fileStorage.ts` to fully utilize IndexedDB, restoring native FileSystemDirectoryHandle capabilities.
- Created `getDirectoryName()` and `getDirectoryFullName()` methods in `src/lib/fileStorage.ts` to surface the connected folder's identifier. (Note: Absolute paths are obscured by browser security, so both currently return the local folder name.)
- Exported the newly created directory properties down via the `Welcome.loader.ts` to dynamically render inside `FolderConnectorStatus.tsx`.
- Created a `src/lib/sessionStorage.ts` generic utility script to mirror `localStorage.ts` behavior as per user request.
